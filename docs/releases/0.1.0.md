# ModSim 0.1.0 release notes

Version 0.1.0 is the initial pre-alpha Python distribution of ModSim, a framework
for modular and multi-robot simulation.

## Installable starter workflow

- Install the `modsim-robotics` wheel without cloning the repository. Python
  imports use `modsim_robotics`; the CLI is `modsim-robotics` and the standalone
  desktop command is `modsim-robotics-studio`.
- Run `modsim-robotics setup` to prepare the local ModSim home and materialize
  the bundled Generic Cube RobotPack at
  `~/.modsim/robot_packs/modlab/generic_cube/0.1.0/`.
- Setup seeds `config.toml` with the RobotPack library location. List installed
  IDs, versions, and paths with `modsim-robotics pack list`, then select a name
  such as `generic_cube` on each Studio, runtime, docking, validation, or view
  command. Version-qualified names and explicit paths are also supported;
  missing or ambiguous selectors never choose a robot implicitly.
- Select another home with `--home PATH` or `MODSIM_PATH`; legacy `MODSIM_HOME`
  remains a fallback. Repeated setup preserves a valid starter and existing
  configuration. Setup prints shell persistence instructions without editing
  profiles or environment variables automatically.
- Inspect and validate the starter, then run mock docking using installed
  package data. The core workflow needs neither MuJoCo nor a desktop display.

For wheel-based installation, install a supplied
`modsim_robotics-0.1.0-py3-none-any.whl` file into an active virtual environment.
After this version is published to PyPI, the package-index command is:

```bash
python -m pip install "modsim-robotics==0.1.0"
```

The [installation guide](https://github.com/modlab-upenn/ModSim/blob/main/docs/how-to/installation.md)
describes virtual environments, optional extras, and the starter path.

## Framework and optional applications

The distribution provides strict RobotPack YAML loading, validation, saving and
export, URDF import, canonical world state and events, connector lifecycle
semantics, a mock backend, and immutable topology and lattice views.

The `mujoco` extra requires MuJoCo 3.3.3 or newer within the 3.x series and adds
physics dependencies for the packaged adapter, including fixed and hinge
constraints and bounded joint-effort commands. The
`studio` extra adds Studio's integrated **Robot Pack** and **Runtime** workspaces,
with the Runtime Inspector also available as a standalone application.
Core APIs remain independent of these optional simulator and GUI dependencies.
Ruff belongs to development tooling rather than the runtime dependency set.

In Studio, select a backend, demonstration, module type, and model view, then
choose **Validate runtime** and **Start simulation**. A missing topology recipe
can be added explicitly, and unsaved edits require **Save and start**. The
embedded Inspector provides **Pause**/**Resume**, **Stop**, retained results,
and **Back to setup** for another run. MuJoCo's native 3D viewer remains a
companion window for the same simulation. Launch settings are session-local;
authored recipes are saved with the pack. Core/headless runs do not require a
model-view recipe.

## Distribution scope and limitations

Generic Cube is the bundled public starter. SMORES-EP and M-Blocks mechanical
asset packs are excluded from the wheel and source distribution. Their scenario
code and documented experiments require separately supplied compatible packs;
an installed package does not provide those larger assets automatically.

The full repository test suite uses source-checkout fixtures and is not shipped
in the source distribution. Release preparation checks the built wheel and
source archive with isolated installation and starter-workflow smoke checks.

Current limitations include:

- No remote community RobotPack catalog or automatic pack-download command.
- No Isaac Sim integration or general three-dimensional reconfiguration planner.
- No continuous magnetic interaction model; attachment uses the implemented
  connector and backend constraint semantics.
- No MuJoCo execution for compliant, ball, or custom connections, and no
  position/velocity joint-control implementation.

Documentation sources are maintained in the
[repository docs](https://github.com/modlab-upenn/ModSim/tree/main/docs).
Hosting the generated Docusaurus manual is separate from package releases.
